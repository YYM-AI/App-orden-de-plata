# Product boundary

Clymo Patrimonio organizes declared synthetic financial positions. It does not execute transactions, provide advice, detect suspicious activity, or integrate with Clymo Alerts.

The root repository contained a small Patrimonio presentation and a Sites/Vinext component scaffold, not an identifiable Alerts implementation. The latest user instruction requires preserving all 76 uploaded files. Milestone 1 therefore lives in `clymo-patrimonio/` with its own package, lockfile, Next routes, types, lint/format/test configuration, domain, data, storage, docs, environment example and build commands. No root source is imported or modified. `scripts/check-boundary.mjs` rejects imports outside this application and imports naming Alerts.

The PDF roadmap's production gates remain unapproved. The user's detailed synthetic milestone and later explicit authorization take precedence over its conditional build sequence. This does not authorize real documents or a production release.

Only fictional names, identifiers prefixed `DEMO-`, approved fictional USD/UF rates and a fictional ETF are supplied. Familiar institution names identify the illustrative fixture and do not imply a partnership or supported connection. Arbitrary file upload and credential controls do not exist.

No paid APIs, infrastructure, public registration, OCR, real PDF extraction, live bank/broker/market/FX calls, alerts, analytics, tax, trading, transfers or automatic property valuation. No public deployment.

The five proposed future PDF template slots limit automatic format support only. There is no five-account, institution or manual-source cap. Categories are a typed extensible taxonomy, not a user source limit.
